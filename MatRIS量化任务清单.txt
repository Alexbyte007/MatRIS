MatRIS sAlex Fuse 优化任务清单

更新时间：2026-05-24

本文件现在只维护 MatRIS sAlex 的纯 fuse / CUDA glue 优化主线。

从本次更新开始，后续不再继续做量化优化；W8A8/W4A8、fake quant、torchao、scaled epilogue 等内容只作为历史归档和 no-go 参考。新的优化工作只围绕 FP32 teacher 路径上的 fuse、module macro、layout / autograd glue、CUDA kernel 边界展开。

一、当前结论

1. 当前主线：纯 FP32 fuse 优化
   - 当前可复刻的纯 fuse 版本是 `p71_latency_pruned_fusion_only` + `p28_p26_all_ffn_mlp_input_grad_only`。

二、固定评测口径

1. 最终测速
   - 只看 teacher 路径：`MatRISCalculator(task="efsm")` / ASE 调用。
   - 当前脚本：`test/eval/infer_salex_lmdb_quant.py --measure-time`。
   - 报告最终加速比必须使用 `latency_ms_mean`、`latency_s_total` 或 `throughput_structures_per_s`。
   - 当前 summary 的 `timing` 已显式写入 `num_timed_samples`、`latency_ms_total`、`latency_s_total`；当两组 success 数相同，mean 耗时加速比与总测量段耗时加速比等价。
   - 第一阶段先跑 limit500；limit500 明确赢，再跑 limit5000。
   - 同一个对比组必须固定 dataset、limit、sample_seed、task、precision 和 GPU 记录。

2. 中间 profile
   - `profile_salex_pipeline.py` 只作为 kernel/debug profile，不能作为最终收益判断。
   - 进入端到端前，优先使用 `test/eval/profile_matriscalculator_pipeline.py` stage profile。
   - 不能把 profile-only 收益写成最终端到端收益。

3. 多卡运行约束
   - 后台实验必须显式设置 `CUDA_VISIBLE_DEVICES=<gpu_id>`。
   - 不同实验必须使用不同 `RUN_NAME`、结果目录、summary 文件和 log 文件。
   - 同一个对比组尽量不要跨 GPU 混跑；如果跨 GPU，summary 必须记录 GPU id。

四、后续主线：只做 fuse 优化

1. 优先方向
   - 更大的 module-level fuse 边界，而不是单个小 kernel 小修。
   - attention / refine block 内的等价 C++/CUDA macro。
   - forward + backward + input-grad 一起考虑，避免 forward 快、force/stress backward 吐回收益。
   - 减少 autograd glue、layout marker、reshape/contiguous、CPU range 和小 op 调度成本。
   - 保持 FP32 数值路径，不引入量化误差变量。

2. 候选边界
   - `attn_line` 完整边界：

```text
edge_update
-> alpha_projection
-> attention_reduce
-> node_update
-> residual
```

   - `refine_line` / `refine_atom` 内 FFN + nonlinear update 的更大边界。
   - full block macro 需要统一考虑：

```text
node_update backward
-> attention backward
-> edge_update backward
-> alpha_projection backward
-> residual gradient merge
```

3. 当前不要做
   - 不再扩大 W8A8 target 名单。
   - 不再做 W4A8 / W4A4 / FP4 / NVFP4。
   - 不再做 fake quant、torchao、activation calibration、quant target sweep。
   - 不再做只对单个 Linear 或单个 second-tail 的量化替换。
   - 不再把 isolated FFN / grouped small-GEMM / wrapper 级小修作为主线。
   - 不再把 `profile_salex_pipeline.py` 的局部收益直接升级为端到端候选。

五、历史量化结论归档

以下内容不再作为后续主线，只保留为历史判断依据。

1. 曾经的安全 W8A8 候选

| candidate | replaced Linear | latency ms | speedup vs same-run FP32 | status |
|---|---:|---:|---:|---|
| `refine_blocks_8_9` | 4 | `84.566677` | `1.020170x` | 历史 best safe W8A8，不再继续 |
| `attn_line_blocks_8_9` | 4 | `84.674246` | `1.018874x` | 历史备选，不再继续 |
| `refine_blocks_8_9_plus_attn_8_9` | 8 | `85.224064` | `1.012301x` | PASS but not mainline |
| `p8d full saved-pre` | 24 | `87.057215` | `0.990985x` | 精度 PASS 但速度不保留 |
| `refine_block_9` | 2 | `87.488758` | `0.986097x` | 历史小 PASS，不再作为最快候选 |

2. 停止量化的原因
   - 单独替换几个 Linear 太窄，收益容易被 pack、dequant、saved-pre backward、input-grad、autograd glue 抵消。
   - 大范围 refine/attn second-tail 组合没有线性叠加。
   - atom/node 更敏感，且之前没有证明端到端收益。
   - A800 不支持 Blackwell NVFP4 Tensor Core 原生收益。
   - 当前可稳定汇报的主要收益来自 pure fuse / CUDA env 优化，而不是量化本身。

下一阶段优化策略：从 Python manual VJP 转向 CUDA input-grad/macro 算子

前面 P99B/P101/R1/R2/R3 已经说明：只在 Python/PyTorch 层用 `torch.autograd.Function` 包边界，correctness 可以做对，但端到端收益不稳定。原因是底层仍然会触发大量 `index_select`、`cat`、`index_add/scatter`、MLP tail backward 等小 CUDA kernel 和中间 tensor materialize；Python manual VJP 只是换了 autograd 调度方式，没有真正减少主要 memory traffic/kernel launch。

因此后续不再优先做新的“纯 Python manual VJP macro”。下一步任务改为：在已有 `matris_op` CUDA 扩展里新增或扩展 input-grad/macro 算子，先做局部 CUDA kernel，再逐步扩大边界。每个 CUDA 候选都必须先过单 block correctness harness，再跑 `infer_salex_lmdb_quant.py --measure-time` 端到端。

优先级 1：attn_line CUDA macro

继续把 `attn_line` 作为第一优先级，但实现方式从 A3-lite manual VJP 改成真正 CUDA 算子。当前依据：

- `no CUDA fused line attention` 慢 `13.27 ms`，line attention 是最大信号。
- P101 A3-lite no-node-input limit5000 为 `85.018572 ms`，说明局部 CUDA gather/cat 是有一点收益的。
- P99B/P101 证明 module 级 Python VJP 不稳定，下一步必须把 gather/cat/scatter/softmax backward/input-grad 边界继续下沉到 CUDA。

建议拆成：

| 版本 | CUDA 边界 | 目标 | 验证 |
| --- | --- | --- | --- |
| A-CUDA1 | `line_edge_gather_cat` backward/input-grad + alpha projection input-grad | 消除 attention 前 gather/cat 与 projection backward 的小 kernel/materialize | `check_attn_line_a3_correctness.py` block0/block9；limit500 |
| A-CUDA2 | segment softmax weighted-sum backward CUDA 化/合并 | 减少 attention_reduce backward 的 scatter/gather 和中间 alpha/value 梯度写回 | 同上；若收益 >1ms 跑 3 次 500 |
| A-CUDA3 | edge_update input-grad + alpha projection + attention backward 联合 kernel | 做真正有意义的 attn_line input-grad macro，但暂不吞 node_update | 同上；收益 >2ms 再跑 5000 |
| A-CUDA4 | 加入 node_update input-grad/residual | 接近完整 attn_line block CUDA macro | 需要 block0/block9/多样本 harness + 5000 端到端 |

注意：不要再做 recompute 版 A1，也不要只新增 Python wrapper。A-CUDA1/A-CUDA2 的目标是明确减少 CUDA kernel launch、global memory 读写和中间 tensor，而不是只减少 autograd 节点。

优先级 2：refine_line CUDA macro

refine_line 仍有信号，但 R1/R2/R3 已证明 Python manual VJP 路线负收益。后续 refine_line 只在 CUDA 层继续推进：

- `no GatedMLP group refine_line_edge` 慢 `3.31 ms`
- `no MLP group refine_line_node_ffn` 慢 `1.32 ms`
- `no MLP group refine_line_edge_ffn` 慢 `1.63 ms`
- R1/R2/R3 correctness 都能过，但端到端平均不赢，说明需要真正合并 gather/cat/smooth reduce/scatter/input-grad kernel。

建议拆成：

| 版本 | CUDA 边界 | 目标 | 验证 |
| --- | --- | --- | --- |
| R-CUDA1 | refine_line gather-cat + edge_nonlinear_update input-grad | 减少 `edge/atom/source/target` gather、cat 和 GatedMLP input-grad 边界 | `check_refine_line_macro_correctness.py` block0/block9；limit500 |
| R-CUDA2 | smooth multiply + target scatter/index_add forward/backward | 合并 `nonlinear * smooth`、target reduce 和对应 input-grad | 同上；重点看 `grad_smooth/grad_atom` |
| R-CUDA3 | edge_FFN/node_FFN input-grad 与 residual 回传合并 | 减少 FFN input-grad 与 residual 小边界，避免 Python VJP overhead | 同上；收益 <1ms 必须 3 次 500 |
| R-CUDA4 | refine_line full input-grad macro | 把 gather-cat、edge_update、smooth reduce、FFN input-grad、residual 梯度统一到少数 CUDA op | 只有 R-CUDA1/2/3 单项有收益才做 |

R4 备注：`refine_line` 路径没有 `directed2undirected average`，所以原 R4 对 line refine 不适用。directed2undirected glue 后续如果要做，应放到 `refine_atom` 或 atom graph attention/refinement 中。

全局测试口径

每个 CUDA 候选都按以下顺序验证：

1. 单 block correctness harness：先比较 forward 和输入梯度。attn_line 至少检查 `node_out/edge_out/grad_node/grad_edge`；refine_line 至少检查 `node_out/edge_out/grad_node/grad_edge/grad_smooth/grad_atom`。
2. `py_compile` 和 CUDA extension 编译通过后，跑 limit500，固定 `sample_seed=42`。
3. 如果收益 `< 1 ms`，至少跑 3 次 limit500，取平均后再判断。
4. 如果收益 `> 2 ms` 或多个 CUDA 子项累计收益明确，再跑 limit5000。
5. 最终结论只认端到端 `infer_salex_lmdb_quant.py --measure-time`，profile 只用于定位热点。

每次记录必须同时包含：

- `latency_ms_mean`
- `latency_s_total` 或 `latency_ms_total`
- `throughput_structures_per_s`
- `energy_mae_natoms`
- `force_mae`
- `stress_mae`
- 成功样本数/跳过样本原因
